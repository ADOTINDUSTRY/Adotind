# Public website data

The media mount at `/var/www/adotind-media` holds `quote-system.sqlite`, gallery images, customer uploads and drawings. The database holds machine and material rates, price settings, submitted quotes and order requests, inquiries, quote-update signups and gallery configuration. An online price preview stays in the browser's server-side session. Its drawing is staged in the private `quote-drafts` directory, excluded from backups and eligible for cleanup after one day. On a new host, configure periodic cleanup of this directory with systemd-tmpfiles. Prices are recalculated when the preview is opened and when the customer sends the request. If the total or currency has changed, the customer reviews it again. Submission creates a reference of the form `Q-123`, archives the accepted drawing and records the inputs, rates, currency and price breakdown.

The shared mount at `/var/www/site-tracking` holds `tracking.sqlite` for Site Tracking and `neon-shop.sqlite` for the project menu, neon designer settings and submitted designs. Both apps need write access to the shared directory. The ERP's **Admin → Public Website** menu manages the designer and request inbox. An unsent neon design stays in the browser. A customer can download a project file and reopen it later. Sending a design for review stores its settings, measured centreline length, customer contact details, SVG and DXF, and any retail estimate shown at submission. The designer stays behind the existing testing PIN.

## Migration and verification

The public image generates font specimens from its centreline engine. At startup it publishes its font library to the shared database, where **Public Website → Neon fonts** controls which styles are offered. On a PHP installation outside Docker, run `php app/cli/publish-neon-library.php` as the web user after deploying a changed font library. Existing selections and submitted proofs are preserved.

Deploy the database-aware ERP reader and the public site before running `php app/cli/migrate-storage.php` as the public site's PHP user. The importer holds the website storage lock, checks imported totals, checks both databases and then activates SQL storage. It can also run against copies using `php app/cli/migrate-storage.php /path/to/media-copy /path/to/tracking-copy`. Keep pre-migration files as a recovery copy. After activation they stop receiving new entries.

## Back up and restore

On the VPS, `tools/backup-website.py MEDIA_HOST_DIRECTORY TRACKING_HOST_DIRECTORY DESTINATION` uses SQLite's online backup API. It packages all three databases, uploads and inquiry attachments. On a fresh installation, initialize the designer with `php -r 'require "app/lib/neon.php"; neon_db();'` as the public site's PHP user before scheduling this backup. Seven weekday archives rotate in the destination. The VPS schedule uses `/var/backups/adotind-website`. Sessions are temporary and are excluded.

Restore into **empty staging directories** first. From the archive, place `databases/quote-system.sqlite` in the media directory and both `databases/tracking.sqlite` and `databases/neon-shop.sqlite` in the tracking directory. Restore `media/uploads` and `media/inquiries` under the media directory. Use the app's PHP user for writable data. Keep any existing GeoIP lookup under `tracking/geo`, or reinstall that lookup on a new host. Run `PRAGMA integrity_check` on each restored database. Check a saved quote reference and its total, the neon designer settings and a submitted design if present, and the daily ERP report. Connect the verified directories as persistent mounts for the new installation. Preserve the original mounts until the restored site is verified.

The scheduled archives are on the VPS. A separate encrypted backup destination is needed for recovery after loss of the whole VPS.
